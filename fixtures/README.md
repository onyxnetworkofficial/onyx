# Fixtures

Pinned inputs with checksums. Never edit a fixture in place; add a new one.

- `merkle/vectors.json`: shared Rust/Solidity Merkle test vectors (ADR-0003). Regenerate only with
  `ONYX_BLESS=1 cargo test -p onyx-merkle`, and only together with an ADR change.
- `api/`: the query API's shared settlement payloads (`settlement-vector.json`, 2 leaves;
  `multi-leaf-vector.json`, 13 leaves), accepted by `contracts/test/OnyxApiVector.t.sol`.
- `intake/`: the data-submission vectors (`vectors.json`: every answer combination's route, the
  Treasury example) and the recorded Debt to the Penny answer the check pull reads (ADR-0038).
- `markets/vectors.json`: shared stake and futures cases run by the contracts and the website's
  `markets.ts` (ADR-0042).
- `ops/rehearsal-gas.json`: gas measured in the Base Sepolia fork rehearsal, behind the run plan's
  budget (THREATS RESAPI-R1-5).
- `revenue/`: revenue split vectors, the contributor-pass policy and the pricing defaults, each
  kept equal to the Rust defaults by a test (docs/spec/revenue.md).
- `settlement/vectors.json`: shared Rust/Solidity settlement vectors (ADR-0022).
- `prepaid/vectors.json`: prepaid voucher digests and signatures (test keys from public labels),
  checked by `onyx_api::prepaid` and `contracts/test/OnyxPrepaid.t.sol` (ADR-0046).
- `dated/salted-vectors.json`: salted label rows (format 3, synthetic) run by onyx-labels, the
  node and the browser (ADR-0037 amendment 3).
- `commit/vectors.json`: shared Rust/Solidity commitment binding and commit hash vectors (ADR-0011).
  Regenerate only with `ONYX_BLESS=1 cargo test -p onyx-core`, and only together with an ADR change.
- `reserves/headers-969839-971207.json`: proof-of-work-checked block headers for the reserve
  serving check's confirmation depth (ADR-0037; `scripts/build-reserve-headers.py`).
  `dated/vectors.json`: shared vector of the dated label-set format (synthetic). Regenerate
  only with `ONYX_BLESS=1 cargo test -p onyx-labels`, and only together with an ADR change.
- `eth/` (ADR-0044): `window-26225261-26225560.manifest.json` (the fetch record and SHA-256 of
  all 601 raw JSON-RPC answers of the website's Ethereum window; the answers themselves, 53 MB
  gzip, are refetched by `scripts/refresh-eth-onchain.py`) and `blocks-26225268-26225270/` (three
  of those blocks in full, gzip of the raw answers, with their manifest), which
  `tests/golden_eth_chain.rs` checks and reruns. Never edit; fetch a new window instead.
- `btc/`: Bitcoin blocks 921080-921082 (see btc/README.md). `labels/`: test label sets v1 (120 labels) and v2 (9,850 labels, 4 companies; see PROVENANCE.md).
  `labels/test.onyx.entities.btc.v3.json`: label set v3, dated (ADR-0037 Amendment 1), built from
  the issuers' own roster snapshots in `rosters/` (one folder per source, each with a
  `snapshots.json` naming every raw snapshot's URL, dates, height and hashes; `rosters/deny.txt`:
  roster addresses a government filing names; `rosters/deny.basis.json`: the roster addresses and
  filings file it was computed against, which the listings re-check on every build). Rebuild with `scripts/build-rosters.py listings`
  and `examples/build-label-set-v3.rs`; see labels/PROVENANCE.md v3.
- `golden/btc-entity-balance-921080-921082.json`: expected output of the reference recipe on the
  above (recipe id, input hash, shard id, root, rows). Cross-checked by an independent Python
  recount on 2026-10-06. Regenerate only with a recipe or registry change. Re-blessed 2026-10-08
  (loop 12): registry root now covers proof rules and entity keys, so only `shard_id` changed.
  Re-blessed again (loop 13): label set renamed to `test.onyx.entities.btc`, so `input_keccak` and
  `shard_id` changed; root and rows unchanged.
- `golden/btc-entity-flow-series-921080-921082.labels-v2.json`: expected output of
  `btc-entity-flow-series` on the same blocks with label set v2 (one row per company per touched
  block). Recounted row for row by `scripts/recount-entity-flow-series.py` inside the test
  (`tests/golden_series.rs`). Regenerate only with a recipe change.
  Re-blessed (loop 14): registry root now covers the network domain and full proof vectors, so only
  `shard_id` changed.
  Re-blessed (loop 15): 2 more proof vectors in the registry root; only `shard_id` changed.
- `claims/vectors.json`: golden Borsh bytes of every `VerificationMethod` (tags 0-5) and one claim
  (L2R-F10). Regenerate only with `ONYX_BLESS=1 cargo test -p onyx-core`, and only with an ADR change.
- `bip322/`: official BIP-322 vectors (CC0, see bip322/README.md). `eip191/`: EIP-191 vectors made by Foundry cast.
- `registry/vectors.json`: shared Rust/Solidity `OnyxRegistry` vectors (ADR-0030): metric keys, the
  Treasury feed template id and the preflight fuel rule. Generated by
  `adapters/source-fiscaldata/tests/registry_vectors.rs`; regenerate only with an ADR change
  (`ONYX_BLESS=1 cargo test -p onyx-source-fiscaldata --test registry_vectors`).
- `pools/pool-allowlist.json`: the reviewed pool companies of the bitcoin-data/mining-pools list
  (MIT, branch `generated`; notice in `pools/LICENSE-mining-pools.txt`, decisions in
  `pools/PROVENANCE.md`), built by `scripts/build-pool-allowlist.py` from the pinned upstream
  file, which is not committed (it names people). The pool table of `btc-pool-blocks` is built
  from it (ADR-0032).
- `btc/coinbase-970019-970029.json`: coinbase proofs (header, coinbase transaction, Merkle branch)
  of 11 mainnet blocks, exported by `examples/export-pools.rs proofs` from our node's raw blocks.
  The range was chosen because every coinbase carries only a pool's own tag and pays at most two
  outputs: a committed fixture must never carry a person's coinbase text (POOL-R1-F2;
  `tests/pool_review.rs` enforces it).
- `golden/btc-pool-blocks-970019-970029.json`: expected output of `btc-pool-blocks` on those
  proofs (recipe id, table hash, root, blocks per pool), recounted by
  `scripts/recount-pool-blocks.py` inside `tests/golden_pools.rs`. Regenerate only with a recipe
  or table change (`ONYX_BLESS=1 cargo test -p onyx-source-btc --test golden_pools`).
- `signed/vectors.json` and `signed/traces.json`: level-3 signed payloads and differential traces
  shared with `contracts/src/OnyxSignedBook.sol` (ADR-0028 amendment 6). Written by
  `crates/onyx-coordinator/tests/level3_chain_book.rs`; regenerate only with an ADR change:
  `ONYX_BLESS=1 cargo test -p onyx-coordinator --test level3_chain_book`.
- `track/commitment-vectors.json`: three chained Borsh `TrackCommitment`s and their hashes (ADR-0036
  amendment 3), read by `contracts/test/OnyxSignedBookTrack.t.sol` (the book hashes them alike).
  Regenerate only with an ADR change (`ONYX_BLESS=1 cargo test -p onyx-track commitment_vectors`).
- `tlock/`: time-lock known-answer vectors (ROADMAP C50): drand/tlock (Go) and tlock-js
  ciphertexts, drand quicknet and quicknet-t chain info and published round signatures (all
  verbatim, sources in `tlock/vectors.json` and `tlock/PROVENANCE.md`), and Onyx's own zero-tail
  vectors (`tlock/onyx-zero-tail.json`; regenerate only with a scheme change:
  `ONYX_BLESS=1 cargo test -p onyx-tlock --test interop`).
