# ADR-0006: x402 payments via the Rust `x402-axum` crate, TypeScript sidecar as fallback

## Status
Proposed, 2026-10-06 (M0). Superseded in part by ADR-0023 (M7, 2026-10-10): own x402 v2 types
behind a `Facilitator` trait instead of `x402-axum`; the trait boundary stays.

## Context
The prompt asked for Rust (axum) with x402, and a TypeScript sidecar only if no solid Rust
implementation exists. RESEARCH.md §3 (x402) found:
- Official x402 repo (x402-foundation/x402, Apache-2.0) has TypeScript, Python, Go and Java SDKs, no Rust.
- Community `x402-rs` (Apache-2.0) publishes `x402-axum`, `x402-reqwest` and `x402-types` 2.0.2 on
  crates.io, supports protocol v1 and v2 and EVM chains including Base. No audit found.
- The CDP facilitator supports Base Sepolia.

## Decision
Use `x402-axum` inside `onyx-api` for testnet. Pin exact versions. Wrap it behind an
`onyx-api` trait (`PaymentGate`) so we can swap to the official TypeScript middleware
(`@x402/express` or `@x402/hono`) as a sidecar without touching handlers.

## Why
- Keeps one language and one process for the API.
- Testnet USDC only, so the risk of an unaudited crate is low now. Before any mainnet use,
  either audit it or move to the official SDK.

## Consequences
- Track upstream protocol changes; `x402-rs` last pushed 2026-07-13, so it may lag the official v2.
- M7 spike must confirm: Base Sepolia USDC asset, payment verification, and settlement through a facilitator.
