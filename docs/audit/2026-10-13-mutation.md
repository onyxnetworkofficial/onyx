# Mutation testing, 2026-10-13 (ROADMAP L4)

Branch `mutants` from main `b2082cb` (runs on 2026-10-14). Free, open-source tools only.
cargo-mutants changes one operator or function body at a time and runs the crate's tests; a
mutant the tests do not notice ("missed") is logic no test pins. Result: **2,329 mutants tried in the scoped code; kill rate (caught or timed out, of the viable ones) rose from 69.7% to 84.9%** with 35 new tests (and new assertions in existing ones) across 8 crates; part of the after runs could not run for disk space (Results). Every surviving mutant in onyx-core is now killed; onyx-merkle, onyx-labels, the reserve crates and the serving check have only equivalent or test-cost survivors left. The weak spots are onyx-coordinator `validate.rs` and `round.rs`, whose own crate tests barely touch them (18.6% and 0% before; they are tested end to end from onyx-source-btc), and the draw-invariant branches that only the `revlog_r8` property test reaches (THREATS MUT-1, MUT-2). One finding beyond test gaps: the x402 EIP-712 digest is byte-identical to Foundry's (a signature from `cast wallet sign --data` equals ours), which no test checked before.

## Tool and setup

| Item | Value |
|---|---|
| cargo-mutants | 27.1.0 (`cargo install --locked cargo-mutants`, MIT) |
| rustc / cargo | 1.98.0 |
| Foundry (independent EIP-712 signer for one vector) | cast 1.8.5 |
| Machine | 12 cores shared with other jobs (load 10 to 35 during the runs), 60 GB RAM |

Every run: `systemd-run --user --scope -q -p MemoryMax=12G`, `--jobs 3 --jobserver-tasks 8`.
cargo-mutants copies the tree into `$TMPDIR` and builds each copy in its own target, so
`CARGO_TARGET_DIR` is left unset for the runs and `TMPDIR` points at `target/mutants-tmp` in
the worktree (`/tmp` is a 31 GB RAM disk here). Two settings make the runs practical, neither
changes a verdict:

- `CARGO_PROFILE_DEV_DEBUG=0`: no debug info in the copies (about 10 GB less per copy).
- A test runner (`CARGO_TARGET_X86_64_UNKNOWN_LINUX_GNU_RUNNER`) that points the test
  binaries' own `TMPDIR` back at the RAM disk: the onyx-api unit tests fsync journals, and
  ran 270 s on the NVMe copy against 12 s on tmpfs (measured with the same binary).

## Tests added

35 new test functions and new assertions in existing ones. What each kills:

**onyx-core** (107 survivors, all killed)
- `claim.rs` `quorum_bounds_at_the_edges`: threshold above the source count, 3 and 5 of 5, a
  duplicated source, two sources with identical obligations (R-RIGHTS-4 must only refuse a
  difference); evidence with a zero hash or a bad kind.
- `feed.rs` `day_number_edges`, `date_lag_bounds`, `template_validate_checks_each_field`: the
  whole `DateLag::validate` and `FeedTemplate::validate` were untested in the crate (replacing
  them with `Ok(())` survived); the epoch, 1900/2000/2100 century rules, leap days, coverage
  edges, a one-day window, a fixed feed's `decay_start`.
- `proof.rs`: every length and range limit of `ObservationSpec::validate` at its edge
  (URL 512, selector and subject 256, value 1,024 bytes, scale 38, observers 255), both window
  ends of `Observation::check`, `MarketPolicy::of` with a repeated level.
- `registry.rs` `registry_uniqueness_and_lookups`: one canon per namespace, one proof per
  namespace and per chain, `proof_for_chain`, built-in proof types, `entity_count`; a dropped
  revocation keeps the honest key's row with the same statement hash.
- `source.rs` `snapshot_rules` (no test module before), `commitment.rs` memory floor,
  `rights.rs` 256-byte attribution, `signed.rs` 253-byte origin host, `value.rs` scale 38,
  `hash.rs` `0x` hex printing.

**onyx-merkle**: `leaf_count` equals the row count.

**Reserve serving check** (`adapters/source-btc`, `reserve-schema`, `reserve-serve`)
- `ReserveGate::claims` was reached only through `KNOWN_GATES`: `the_gate_claims_reserve_bindings_only`
  (by schema, by build, neither); the `not_cross_checked` reason text.
- `ReserveParams::is_canonical` had no test in its crate.
- The same-block second scan (`reconcile_at_or_after`, basis `second-node-rescan`) was never
  run: a re-scan of the same block reconciles, one satoshi off drops the entity, another
  block, another set, flows, or a lower height add nothing; a record that compared no address
  does not count.
- `flows_from_jsonl` (the flows file the server loads) had no test: it equals the fixture's
  own sum, refuses a height gap or a wrong `prev`, skips blank lines.
- `decode_shard` range rules one at a time (start at the pinned start, reversed range, rows of
  another base height), right params with rows that do not add up, `check_chain` gaps,
  reversals, renamed entities and rows naming another base or end height, a zero running
  balance allowed and one satoshi below refused, label-set name/version and empty rows.

**onyx-labels**: attestation window equal to the proof rule's maximum, address signature at
the size cap, `parse_height`/`parse_nonce` grammars, signing helpers (both recovery ids),
`LabelSet::validate` header/confidence/attestation-count edges, `VersionLog::verify` first
entry and repeated round, `diff` interleaving and tails, `score_all` (untested: replacing it
with an empty map survived), `eligible`, the means, the log floor for several candidates,
`log2_fixed` past 2^62.

**onyx-api**
- `x402.rs` `the_eip712_digest_matches_an_independent_signer`: our signature over the test
  authorization equals Foundry's (`cast wallet sign --data`, RFC 6979): replacing the
  type hash or the address word with zeros survived before, because signing and verifying
  shared the same digest code.
- `arrival.rs`: `pairing` refuses a Transfer-shaped log of another contract, another token
  event (Approval), a Transfer from someone else or with a fourth topic; `first_block_at`
  edges; `logged_use` over one block; `judge` at each block edge, the FINAL_SCANS count and
  the one extension back.
- `gate.rs`: a gate name or metric registered once; rows missing from the store are skipped;
  in a run left incomplete, an answer whose root changed or whose shard left the catalog is
  dropped and not counted as kept; the removed link's own answer after an indexer removal.
- `intents.rs`: clock skew at the bound, a proof served only before its window ends and
  dropped by the pass at its end, a receipt journal that breaks mid-pass.
- `x402.rs`: a header of exactly 16 KiB decodes; a failed settle under a 400 is a refusal, not
  an outage; the mock facilitator checks both versions and the real clock; transport caps.
- `indexer_tests.rs`: a served shard is not read again on an ordinary poll.

**onyx-coordinator**: `gone_proof` and `confirm_announced` from one final block at every edge
(window end, beacon height; a mock whose latest read fails); `release_draw` refuses a proof
showing the draw on chain, a final block below its beacon height, another draw's zero beacon,
an unknown round, and a release of an opened draw; `draw_observers` never returns a partial
set; `check_draw` counts only bonded members; `sync_draws` with a held draw; a scale-0 feed is
backed only by an integer; `validators_deterred` needs each condition; a miner's slash is not
capped by validator bonds (the `apply` guard set to `true` zeroed every miner slash and
survived); held work released at its height; a contract mirror's ledger id.

## Survivors left
