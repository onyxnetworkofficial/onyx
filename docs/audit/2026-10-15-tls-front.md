# TLS in front of onyx-node: local proof, 2026-10-15 (ROADMAP L11, THREATS M7-7)

Branch `tls-front` from main `9717d9f`. Result: **behind `deploy/caddy/Caddyfile`, onyx-node is
reached only over TLS; plain HTTP redirects; bodies over 1 KiB get 413; rate limits key on the
forwarded client and a client's own `X-Forwarded-For` buys nothing.** onyx-node refuses a
non-loopback `ONYX_LISTEN` without `ONYX_ALLOW_PLAIN_HTTP_PUBLIC=1`.

What this run is **not**: a public deployment. The certificate came from Caddy's local CA
(`tls internal`), not from Let's Encrypt; the domain, ports 80/443 and the ACME challenge are
untested until the project owner picks the host and domain (launch checklist LC-8). Everything ran on the dev
box's loopback; nothing was reachable from outside (Caddy bound `127.0.0.1`, see `ss` below).

## Setup

```sh
scripts/demo-local.sh --serve --export-node $S/node-export      # anvil + one finalized shard
# onyx-node from the export, behind the proxy:
set -a; . $S/node-export/node.env; set +a                       # ONYX_LISTEN=127.0.0.1:8404, dev chain
ONYX_TRUSTED_PROXIES=127.0.0.1 ONYX_PUBLIC_URL=https://localhost:18443 \
  ONYX_INDEX_EVERY_SECS=2 ONYX_INDEX_HEALTH=summary target/release/onyx-node
# Caddy with the shipped file; only the env differs from production:
XDG_DATA_HOME=$S/caddy-data XDG_CONFIG_HOME=$S/caddy-config \
ONYX_CADDY_DOMAIN=localhost ONYX_CADDY_TLS=internal ONYX_CADDY_UPSTREAM=127.0.0.1:8404 \
ONYX_CADDY_HTTP_PORT=18080 ONYX_CADDY_HTTPS_PORT=18443 ONYX_CADDY_BIND=127.0.0.1 \
  caddy run --config deploy/caddy/Caddyfile --adapter caddyfile
CA=$S/caddy-data/caddy/pki/authorities/local/root.crt           # Caddy's local root, for curl --cacert
```

`$S` is a scratch directory, `$W` the worktree. `PAY16K` is 16,384 `A`s (the largest
`PAYMENT-SIGNATURE` onyx-api takes), `PAD40K` 40,000.

Found and fixed during the run:
- **`request_body max_size` alone did not refuse a 2 KiB body** (first run: 200). onyx-node answers
  a GET without reading its body, so Caddy returned that answer before reading past the cap; only
  a 1 MiB body got 413. `request_buffers 4KiB` makes Caddy read the body before dialing; then
  every body over 1 KiB is 413 (THREATS TLS-1).
- **Caddy's automatic HTTP->HTTPS redirect server did not get the `servers` options** (its log:
  `remaining_auto_https_redirects`, protocols h1 h2 h3, default timeouts). The file now writes the
  redirect as its own `http://` site block, and `caddy adapt` shows both servers with the 10 s
  header timeout and the 32 KiB header cap.
- **Caddy's default header cap (16 KiB) is below a full payment header plus the rest**: set to
  32 KiB; a 16 KiB `PAYMENT-SIGNATURE` passes (200) (TLS-4).

A fresh review subagent then found (fixed before the final run):
- **In Docker the proxy's peer is the bridge gateway, not 127.0.0.1** (it saw
  `::ffff:172.17.0.1`): with `ONYX_TRUSTED_PROXIES=127.0.0.1` every client would share one bucket.
  deployment.md now says to trust the gateway address in Docker (TLS-7, docs only; not run here).
- **Caddy's own errors (413, 502) skipped the deferred `header` handler** (no HSTS,
  `server: Caddy`): `handle_errors` sets the same headers (sections 5 and 7 show them) (TLS-8).
- **HTTP/2 allows 250 streams per connection**, so a per-address connection cap would not bound a
  client's requests in flight: the file serves HTTP/1.1 only (TLS-8).
- The drift test read only the first `path`/`method`/`reverse_proxy` line: it now requires
  exactly one of each.

`onyx-node tests/caddyfile.rs` pins these: every router path proxied and nothing else,
`GET HEAD` only, the redirect block, `request_buffers` above `max_size`, the header cap, the write
and upstream timeouts against `ApiConfig::default()`, no `trusted_proxies` and no
`X-Forwarded-For` rewrite. Each of four edits to the file (drop `/v1/export/*`, header cap
16 KiB, `request_buffers 1KiB`, add `POST`) made it fail.

## Not covered

- A real ACME certificate on the real domain, ports 80/443 from outside, renewal: needs the host
  and domain (LC-8, Needs the project owner). Re-run sections 3-6 against it on the launch box.
- A per-client connection cap in front of onyx-node: stock Caddy has none, and onyx-node exempts
  its proxy (AUD-1R-F1); a host-firewall rule is the plan (THREATS TLS-2).
- The Docker variant behind Caddy (bridge-gateway trusted proxy, TLS-7) was not run; the
  documented check is two clients getting separate limits.

listen on `0.0.0.0` inside the anvil container's namespace, published on 127.0.0.1) and checks that

onyx-node-btc`), then `ONYX_DOCKER_TAG=tlsfront ONYX_RESERVE_DIR=<fixtures-live/tail>
scripts/docker-smoke.sh`: exit 0, `DOCKER SMOKE PASSED`, 23 PASS lines, among them `PASS a 0.0.0.0
listen address without ONYX_ALLOW_PLAIN_HTTP_PUBLIC=1 is refused in both images (M7-7)`. The anvil
fork read Base Sepolia state over HTTPS; nothing was broadcast. The images predate the last
Caddyfile and docs edits, which they do not contain.
