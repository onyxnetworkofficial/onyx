# Soak and chaos test, 2026-10-14 (ROADMAP L6)

Branch `soak` from main `b2082cb` (main merged in at `407f83b`). Result: **four bugs found and
fixed, each with a regression test** (SOAK-1 to SOAK-4); the confirmation run after the fixes
(run 3, 150 minutes) held every invariant it checks. A fourth run on the tree merged with main was cut short by a
session restart and left no data, so the merged tree was not soaked (open, SOAK-7). Money invariants held in every run: no answer without a proven payment, no
authorization booked twice, no paid authorization left unbooked. Everything ran on a local
anvil fork of Base Sepolia (in memory: no transaction reached a public network).

## Bugs found and fixed

| ID | Found in | What happened | Fix and regression test |
|---|---|---|---|
| SOAK-1 (Medium, money) | trial 2 | With self-settle, a settle that landed but whose answer was lost left an open intent; the payer's identical retry got 409 `payment_in_use` "already being settled for another request; this request added no charge". 69 identical retries got it in 20 min; 2 of 1,163 authorizations used on chain were never served. A client that believes the message signs again and pays twice | The identical retry of an open intent gets 503 `payment_pending` with `Retry-After: 30`, never a new settle, and is served from the resolver's proof once the transfer is proven. `tests::soak_1_the_identical_retry_of_an_unknown_self_settle_is_told_to_retry` (409 without the fix) |
| SOAK-2 (Medium, availability) | run 1 | One node error at start stopped `onyx-node` (exit 1): settlement code, registry floors, level-2 pins and OnyxRevenue's code were read once. Behind a node failing 27% of calls, 60 starts in a row failed over 10.6 min | Each start-up read is tried 8 times, 0.5 s doubling to 8 s (about 31 s; `onyx_node::app::startup_step`); a lasting failure still stops the start. `crates/onyx-node/tests/startup_retry.rs` |
| SOAK-3 (Low, memory) | run 1 | TTL caches (settled responses for identical retries above all) dropped expired entries only on a read or when the 65,536-entry / 256 MiB budget pushed them out: onyx-node RSS 7.8 to 39.9 MB in its first 60 min, linear | Expired entries are dropped from the least recently used end on every insert. `cache::tests::soak_3_expired_entries_are_dropped_on_insert` (1,001 entries kept without the fix, 1 with it) |
| SOAK-4 (Medium, availability) | run 2 | The deploy-block check (IDX-R1-4) read state at `deployBlock` on every start; once the deployment was older than the node's state window (anvil: about 4,800 blocks here; a pruned full node: 128), no restart could pass it: onyx-node-btc failed 44 starts in a row from minute 66 to 130, 29 of them with faults off | A passed check is recorded in the bound indexer state file (`deployChecked`) and later starts skip it. `indexer::tests::soak_4_a_restart_does_not_need_the_deploy_blocks_state_again` |

Review notes (L6 review, no blocking findings):

- SOAK-2, accepted: the start-up retries stack. A failure that will not go away (a wrong
  code hash, the wrong chain, a node that stays down) now exits only after about 30 s of
  tries per step (8 tries, 0.5 s doubling to 8 s), instead of at once. The message is the
  same, and the supervisor's `Restart=on-failure` keeps restarting as before.
- SOAK-1, a small race, no money effect: the identical retry checks the resolver's proof
  (`IntentLog::proven`) before the open intent (`IntentLog::awaiting`). If the resolver turns
  the intent into its proof between those two reads, that one retry finds neither and takes
  the fresh path, which answers an error once (409 `payment_in_use` or a refused verify on the
  used nonce); nothing is settled or charged, and the next identical retry is served from the
  proof.
- NB1: a second SOAK-1 test uses a facilitator that credits on settle (as `SelfSettle`), with
  and without an authorization check configured
  (`tests::soak_1_a_self_crediting_facilitator_tells_the_identical_retry_to_wait`).
- NB3: when the recorded deploy-block check is reused, the head check (one `eth_blockNumber`:
  the node's head must reach `deployBlock`) still runs, so a node on another network or still
  syncing is refused at every start (asserted in the SOAK-4 test).

Harness bugs found on the way (not product code): a restart that blocked the loop held the
fault profile in place (run 1); the clean-window check counted intents of settles still
running; `report.py` failed on a run shorter than its leak window; booked authorizations were
counted twice (OnyxRevenue's `settle` emits both `Settled` and `Credited`).

## Coverage and limits (open)

- One local anvil fork: no real Base node behaviour (load balancing across backends, real
  rate limits, reorgs: anvil does not reorg, so reorg handling was not exercised here).
- `onyx-node-btc` carried unpaid traffic only (OnyxRevenue has one reporter; two paying
  processes would share a key and its nonces).
- Load is modest (about 3 requests a second, about 0.6 paid settles a second) on a shared box;
  this is a robustness run, not a benchmark (L5).
- `404 unknown_metric` answers a query whose `as_of` is older than every served shard; the
  metric exists. Harmless but misleading (THREATS SOAK-5; fixed 2026-10-16: `404 no_shard_at_as_of`).
- RSS still rose about 5 MiB an hour over run 2's window (allocator, caches inside their TTL);
  a longer run would show whether it levels off (THREATS SOAK-6).
- THREATS SOAK-7 lists what the soak did not exercise (reorgs, a real node, two paying
  processes, higher load).
