## 1. What makes Onyx novel (most important)

**One line:** a peer-run network where anyone can submit any data, others check it, and markets
and apps settle on it, with disputes decided by rerunning the work wherever the data allows it.

| # | Idea | Why it matters | Status |
|---|---|---|---|
| N1 | **Settle by recompute, not by vote, wherever the data allows (see N9).** A disputed value is decided by rerunning a pinned recipe over pinned inputs. Anyone can rerun it, even in a browser. | Prediction markets today resolve disputes by token-holder votes: Polymarket uses UMA's optimistic oracle, and disputed answers go to a UMA token-weighted vote ([Polymarket docs](https://docs.polymarket.com/concepts/resolution), [explainer](https://ariverwhale.substack.com/p/understanding-uma-and-dispute-resolution)). For computable data, Onyx needs no vote. | Built for BTC (M1-M4); browser rerun live on the site |
| N2 | **Markets on data itself ("Polymarket for data").** Anyone can open a market on a data value or on whether a data claim survives validation. Miners, validators and challengers price the truth of data. | Turns data reliability into a price. Bad data becomes a losing bet, not just a bug. | Idea; needs M5 disputes + M6 contracts |
| N3 | **Any data, any source, one pipeline.** Recipes are open WASM; sources are adapters with a rights record; the core is sector-agnostic (ADR-0010). Bitcoin is sample #1. | The same commit-reveal, sampling and proof machinery works for on-chain, web, sensor, model-eval and private data. | Core is generic today; one adapter (BTC) |
| N4 | **A checking method per kind of claim.** Computable (rerun), first-party (the owner signs, like our label attestations), web (zkTLS / TLSNotary proofs of an HTTPS response, [FOSDEM 2026](https://fosdem.org/schedule/event/QZ8NAZ-tlsnotary)), subjective (calibration-scored with a proper scoring rule), private (Cypher reruns in a protected environment). | Honest about what each method proves: a hash shows data did not change, not that it was true. | Rerun + first-party + Brier built; zkTLS and Cypher are ideas |
| N5 | **Rights travel with the data.** Every source carries a rights record whose hash is pinned in each shard; restricted data never enters paid supply. | "Any data" without becoming a piracy network. Matches the Cypher brief: privacy does not create redistribution rights. | `DataRights` + `rights_hash` built |
| N6 | **Contributors own the commons.** Paid per accepted contribution and per use; old data becomes free (time-decay pricing). | Data gets cheaper over time instead of locked forever. | Spec (pricing.md); M7 |
| N7 | **Pooled private supply (Cypher).** Many people contribute encrypted data to a pool that acts as one big miner; Onyx validates its outputs like anyone else's. | Private data can earn without being exposed. | Concept (Onyx + Cypher overview, 2026-10-06) |
| N8 | **Check it yourself, in the browser.** The site runs the network's own Rust code; a customer never has to trust our server. | Trust you can demonstrate in 1 second. | Live on the site |

### N9. The proof ladder: how novel data gets in (2026-10-09, from the project owner's question)
Rerun only works when anyone can get the same inputs. Novel data (a sensor reading, a private
survey, a page only one person can see, a field observation) needs other ways in. Every data point
carries its **proof level**; a market or customer chooses the lowest level it accepts.

| Level | How it is checked | Example | Status |
|---|---|---|---|
| 1. Recomputed | Anyone reruns a pinned recipe on public inputs | BTC exchange flows | Built (M1-M4) |
| 2. Re-observed | Several bonded nodes run the same open fetcher on the same public source in the same window, with sealed answers (commit-reveal) so nobody copies | A public price page, an open API | Idea: fetchers as open adapters |
| 3. Source-proven | The source signs it (first-party key), or a zkTLS proof shows the exact HTTPS response, or a device / secure-enclave signature | Company addresses (built for labels), sensor readings, account facts | Labels built; zkTLS and devices are ideas |
| 4. Bonded claim | The submitter stakes; anyone can challenge with evidence during a window; unresolved disputes go to a randomly drawn bonded panel as a last resort | A field observation, a new dataset nobody else has | Idea; needs M5 |
| 5. Track record | When a fact becomes checkable later, past submitters are scored and slashed; judgments are scored with a proper scoring rule (Brier) | Forecasts, labels, early reports | Brier built (ADR-0016); source track records computed and committed, not served yet (ADR-0036) |

Why it matters: novel data can enter on day one at a lower level and climb as more proof arrives
(for example, a bonded claim that a later source signature confirms). Customers see the level, so
nobody mistakes a claim for a recomputed fact. Open questions: who may run a panel, how big the
bonds are, and whether levels 4-5 can settle money markets at all (default: no, only levels 1-3).

### N10. Onyx vs prediction markets (2026-10-09, from the project owner's question)
Same root idea: money at risk instead of "trust me". Different jobs:
- Polymarket: money on what **will** happen; output is a price (a probability). The final answer
  comes from UMA's optimistic oracle: a bonded proposal, and if disputed, a UMA token-weighted vote
  ([Polymarket docs](https://docs.polymarket.com/concepts/resolution), [explainer](https://ariverwhale.substack.com/p/understanding-uma-and-dispute-resolution)).
- Onyx: money (bonds) on whether **data** is right; output is checked data with proofs, sold per
  call. For computable data the final answer is a rerun anyone can repeat, not a vote; otherwise
  the proof ladder (N9) decides.
- Together: Onyx can be the settlement layer for markets, and adds markets on data itself.
- Pitch line: "Prediction markets price the future. Onyx proves the facts they settle on."

### Guardrails that stay true for "any data"
- Rights first: no third-party data whose license forbids redistribution (hard limit).
- Labels name entities only; no personal data about individuals in public supply.
- Testnets only until contracts are reviewed; no real funds.
